# TG Newspaper

> Агент, который по нажатию кнопки собирает и печатает бумажную газету из новостей выбранных Telegram-каналов за последние сутки.

Идея — дать не экран, а бумагу: по требованию пользователя, а не по расписанию, собирается свежая газетная полоса, свёрстанная агентом самостоятельно — из вчерашних новостей выбранных каналов, без дублей и мусора. Исходная идея, механика и принятые на старте решения — в [docs/project-brief.md](docs/project-brief.md); как проект пойдёт по этапам — в [docs/implementation-plan.md](docs/implementation-plan.md).

## Статус

Идея сформулирована, реализация идёт по этапам. Ключевые технические развилки закрыты (см. ниже), часть решений намеренно оставлена открытой — список в [docs/future-development.md](docs/future-development.md).

## Что должно получиться (первая версия)

- Пользователь открывает локальную консоль и нажимает кнопку "Собрать газету" — никакого расписания и автозапуска, прогон стартует только по этому явному действию
- Агент забирает посты за последние 24 часа **от момента нажатия** из заранее заданного списка Telegram-каналов
- Отсеивает "не новости" — медиа без содержательной подписи, посты без текста, рекламу — и дубли одной и той же новости, разошедшейся по нескольким каналам
- Компонует оставшееся в изображение стилизованной газетной полосы (заголовки, колонки, узоры)
- Отправляет готовое изображение на принтер по локальной сети

## Стек (предварительно)

- **Язык:** Python — экосистема обработки изображений (Pillow/Playwright) и клиентов Telegram там сильнее всего
- **Источник данных:** MTProto под пользовательским Telegram-аккаунтом (Telethon), а не Bot API — см. "Почему MTProto, а не Bot API" ниже
- **Фильтрация "не новостей" и дедупликация:** комбинация — эвристики отсеивают явный мусор (медиа без подписи, пустые посты, копипасты) до вызова модели, LLM решает спорные случаи (новость ли это по смыслу, одна ли это новость, пересказанная разными словами)
- **Рендер изображения:** не выбран — Pillow-шаблон против HTML/CSS + headless-браузер, см. [docs/future-development.md](docs/future-development.md)
- **Печать:** HP Color LaserJet Pro MFP M377dw, только по локальной сети (AirPrint/CUPS/IPP) — облачная печать (HP ePrint) закрыта производителем в январе 2023 года, для этой модели путь через облако недоступен физически
- **Среда выполнения:** основной домашний ПК, локальная веб-консоль (`uv run python scripts/console.py`) с кнопкой запуска; тот же прогон доступен и из терминала (`uv run tg-newspaper`) — постоянно работающий процесс не нужен, скрипт живёт ровно один прогон

## Почему MTProto, а не Bot API

Bot API не даёт боту метода "прочитать историю канала за прошедшие сутки" — бот получает посты только по мере их появления (`getUpdates`/webhook), а не задним числом. Это несовместимо с тем, как должен работать агент: по нажатию кнопки он должен разово забрать историю канала за произвольный период "с этого момента назад", а не держать постоянно работающий процесс-слушатель.

MTProto под пользовательским аккаунтом (Telethon) умеет то, чего нет у ботов, — отдать историю канала за произвольный период по запросу. Поэтому агент — это один скрипт, запускающийся по явной команде пользователя:

1. Пользователь нажимает "Собрать газету" в локальной консоли (или запускает `uv run tg-newspaper` из терминала).
2. Скрипт запрашивает через Telethon историю каждого канала-источника за последние сутки от момента нажатия. Наверстывание пропущенных запусков сознательно не делается — если пользователь не запускал прогон день или дольше, ближайший прогон всё равно заберёт только свои последние сутки, а не восполнит пропуск.
3. Фильтрует, дедуплицирует, рендерит полосу, печатает на принтере по локальной сети.

Обратная сторона: сессия Telethon — это файл авторизации личного Telegram-аккаунта, а не просто токен API, хранить её нужно как секрет. Подробнее — в [project-brief.md](docs/project-brief.md), раздел "Механика", и в [AGENTS.md](AGENTS.md).

## LLM-классификация: Gemini и обход гео-блокировки через Cloudflare

Этап 2 (фильтрация спорных случаев) использует Gemini (бесплатный тариф) — см.
[implementation-plan.md](docs/implementation-plan.md). Настройка ключа — в
`.env.example` (`GEMINI_API_KEY`, `GEMINI_MODEL`).

Если агент работает из РФ, Gemini может ответить `400 FAILED_PRECONDITION: User
location is not supported` (IP/VPN считается неподдерживаемым регионом). Обход —
свой прокси на **Cloudflare Worker**, тот же приём, что и в соседнем проекте
[tg_mail_bot](../tg_mail_bot): Google видит адрес Cloudflare, а не IP агента.

1. Зайди на <https://dash.cloudflare.com> → **Workers & Pages** → **Create** → **Worker**.
2. Дай имя (напр. `tg-newspaper-gemini`), нажми **Deploy**, затем **Edit code**.
3. Вставь содержимое [`cloudflare-worker.js`](cloudflare-worker.js) и снова **Deploy**.
4. Скопируй URL воркера (вида `https://tg-newspaper-gemini.ТВОЙ-АККАУНТ.workers.dev`).
5. Пропиши его в `.env`:
   ```
   GEMINI_BASE_URL=https://tg-newspaper-gemini.ТВОЙ-АККАУНТ.workers.dev
   ```

Проверить воркер вручную:
```bash
curl "https://tg-newspaper-gemini.ТВОЙ-АККАУНТ.workers.dev/v1beta/models?key=ТВОЙ_GEMINI_КЛЮЧ"
```
Должен вернуться список моделей (JSON), а не ошибка региона.

> VPN здесь не используется — Worker сам решает проблему гео-блокировки на
> стороне Google. Отдельный VPN понадобится, только если провайдер блокирует
> сам домен `workers.dev` на уровне сети — это уже другая, менее вероятная проблема.

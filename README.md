# TG Newspaper

> Агент, который каждое утро сам печатает бумажную газету из вчерашних новостей выбранных Telegram-каналов.

Идея — дать не экран, а бумагу: раз в сутки дома появляется свежая газетная полоса, свёрстанная агентом самостоятельно, без участия человека. Исходная идея, механика и принятые на старте решения — в [docs/project-brief.md](docs/project-brief.md); как проект пойдёт по этапам — в [docs/implementation-plan.md](docs/implementation-plan.md).

## Статус

Идея сформулирована, реализация не начата. Ключевые технические развилки закрыты (см. ниже), часть решений намеренно оставлена открытой — список в [docs/future-development.md](docs/future-development.md).

## Что должно получиться (первая версия)

- Раз в сутки, рано утром, ПК просыпается по будильнику, агент забирает посты за последние сутки из заранее заданного списка Telegram-каналов
- Отсеивает "не новости" — медиа без содержательной подписи, посты без текста, рекламу — и дубли одной и той же новости, разошедшейся по нескольким каналам
- Компонует оставшееся в изображение стилизованной газетной полосы (заголовки, колонки, узоры)
- Отправляет готовое изображение на принтер по локальной сети
- ПК завершает работу до следующего пробуждения

## Стек (предварительно)

- **Язык:** Python — экосистема обработки изображений (Pillow/Playwright), клиентов Telegram и системного планирования там сильнее всего
- **Источник данных:** MTProto под пользовательским Telegram-аккаунтом (Telethon), а не Bot API — см. "Почему MTProto, а не Bot API" ниже
- **Фильтрация "не новостей" и дедупликация:** комбинация — эвристики отсеивают явный мусор (медиа без подписи, пустые посты, копипасты) до вызова модели, LLM решает спорные случаи (новость ли это по смыслу, одна ли это новость, пересказанная разными словами)
- **Рендер изображения:** не выбран — Pillow-шаблон против HTML/CSS + headless-браузер, см. [docs/future-development.md](docs/future-development.md)
- **Печать:** HP Color LaserJet Pro MFP M377dw, только по локальной сети (AirPrint/CUPS/IPP) — облачная печать (HP ePrint) закрыта производителем в январе 2023 года, для этой модели путь через облако недоступен физически
- **Среда выполнения:** основной домашний ПК, будится по расписанию, выполняет весь пайплайн одним прогоном и выключается — постоянно работающий процесс не нужен

## Почему MTProto, а не Bot API

Bot API не даёт боту метода "прочитать историю канала за прошедшие сутки" — бот получает посты только по мере их появления (`getUpdates`/webhook), а не задним числом. Это несовместимо с тем, как должен работать агент: ПК спит почти всё время и просыпается на короткий прогон раз в сутки, а не держит постоянно работающий процесс.

MTProto под пользовательским аккаунтом (Telethon) умеет то, чего нет у ботов, — отдать историю канала за произвольный период по запросу. Поэтому агент — это один скрипт, запускающийся по расписанию:

1. ПК просыпается по будильнику (RTC-будильник BIOS/UEFI, резервный вариант — Wake-on-LAN по проводному соединению).
2. Скрипт запрашивает через Telethon историю каждого канала-источника за последние сутки от момента запуска. Наверстывание пропущенных дней сознательно не делается — если ПК не проснулся вовремя или прогон упал, газета в этот день просто не печатается.
3. Фильтрует, дедуплицирует, рендерит полосу, печатает на принтере по локальной сети.
4. ПК выключается.

Обратная сторона: сессия Telethon — это файл авторизации личного Telegram-аккаунта, а не просто токен API, хранить её нужно как секрет. Подробнее — в [project-brief.md](docs/project-brief.md), раздел "Механика", и в [AGENTS.md](AGENTS.md).

# TG Newspaper

> Агент, который по нажатию кнопки собирает и печатает бумажную газету из новостей выбранных Telegram-каналов за последние сутки.

Идея — дать не экран, а бумагу: по требованию пользователя, а не по расписанию, собирается свежая газетная полоса, свёрстанная агентом самостоятельно — из вчерашних новостей выбранных каналов, без дублей и мусора. Исходная идея, механика и принятые на старте решения — в [docs/project-brief.md](docs/project-brief.md); как проект пойдёт по этапам — в [docs/implementation-plan.md](docs/implementation-plan.md).

## Статус

Этапы 0-3 сделаны (сбор истории каналов, фильтрация и дедупликация, вёрстка и рендер газетного номера) — см. отметки в [docs/implementation-plan.md](docs/implementation-plan.md). Печать (Этап 4) и встраивание готового номера в кнопку консоли (Этап 5, п.3) — ещё нет. Часть решений намеренно оставлена открытой — список в [docs/future-development.md](docs/future-development.md).

## Что должно получиться (первая версия)

- Пользователь открывает локальную консоль и нажимает кнопку "Собрать газету" — никакого расписания и автозапуска, прогон стартует только по этому явному действию
- Агент забирает посты за последние 24 часа **от момента нажатия** из заранее заданного списка Telegram-каналов
- Отсеивает "не новости" — медиа без содержательной подписи, посты без текста, рекламу — и дубли одной и той же новости, разошедшейся по нескольким каналам
- Компонует оставшееся в номер — фиксированный объём (4 альбомные полосы A4), не бесконечная лента: LLM оценивает значимость каждой новости, самое важное печатается в первую очередь, длинное-но-важное сокращается нейронкой, проходное — не попадает в номер
- Отправляет готовые изображения полос на принтер по локальной сети

## Стек

- **Язык:** Python — экосистема клиентов Telegram, LLM и headless-рендера там сильнее всего
- **Источник данных:** MTProto под пользовательским Telegram-аккаунтом (Telethon), а не Bot API — см. "Почему MTProto, а не Bot API" ниже
- **Фильтрация "не новостей" и дедупликация:** комбинация — эвристики отсеивают явный мусор (медиа без подписи, пустые посты, копипасты) до вызова модели, LLM решает спорные случаи (новость ли это по смыслу, одна ли это новость, пересказанная разными словами) и оценивает значимость каждой новости (1-5) для отбора в номер
- **Рендер полосы:** HTML/CSS + headless-браузер (Playwright/Chromium) — мозаичная вёрстка (`src/tg_newspaper/layout.py`), не проточные колонки: ширина плитки по значимости новости, высота — по фактическому объёму её текста, полный текст без обрезки. Разбивка на страницы — не оценка, а измерение реальной раскладки в браузере
- **Печать:** HP Color LaserJet Pro MFP M377dw, только по локальной сети (AirPrint/CUPS/IPP) — облачная печать (HP ePrint) закрыта производителем в январе 2023 года, для этой модели путь через облако недоступен физически
- **Среда выполнения:** основной домашний ПК, локальная веб-консоль (`uv run python scripts/console.py`) с кнопкой запуска; тот же прогон доступен и из терминала (`uv run tg-newspaper`) — постоянно работающий процесс не нужен, скрипт живёт ровно один прогон

## Почему MTProto, а не Bot API

Bot API не даёт боту метода "прочитать историю канала за прошедшие сутки" — бот получает посты только по мере их появления (`getUpdates`/webhook), а не задним числом. Это несовместимо с тем, как должен работать агент: по нажатию кнопки он должен разово забрать историю канала за произвольный период "с этого момента назад", а не держать постоянно работающий процесс-слушатель.

MTProto под пользовательским аккаунтом (Telethon) умеет то, чего нет у ботов, — отдать историю канала за произвольный период по запросу. Поэтому агент — это один скрипт, запускающийся по явной команде пользователя:

1. Пользователь нажимает "Собрать газету" в локальной консоли (или запускает `uv run tg-newspaper` из терминала).
2. Скрипт запрашивает через Telethon историю каждого канала-источника за последние сутки от момента нажатия. Наверстывание пропущенных запусков сознательно не делается — если пользователь не запускал прогон день или дольше, ближайший прогон всё равно заберёт только свои последние сутки, а не восполнит пропуск.
3. Фильтрует, дедуплицирует, вёрстает номер, печатает на принтере по локальной сети.

Обратная сторона: сессия Telethon — это файл авторизации личного Telegram-аккаунта, а не просто токен API, хранить её нужно как секрет. Подробнее — в [project-brief.md](docs/project-brief.md), раздел "Механика", и в [AGENTS.md](AGENTS.md).

## Быстрый старт

### Установка (готовое приложение)

Скачайте со страницы [Releases](https://github.com/tiltozavr2545/tg_newspaper/releases): **`TG-Newspaper-<версия>-mac.dmg`** (macOS — перетащите приложение в «Программы») или **`TG-Newspaper-<версия>-windows-setup.exe`** (Windows, права администратора не нужны). Запустите «TG Newspaper»: при первом запуске приложение само ставит [uv](https://docs.astral.sh/uv/), Python, зависимости и Chromium — это **2–3 минуты, нужен интернет**; пока идёт подготовка, в браузере висит страница ожидания, затем она сама открывает консоль на `http://localhost:8420/` с мастером настройки.

Приложение **без цифровой подписи**, поэтому в первый раз система спросит подтверждение:

- **macOS:** правый клик по приложению → «Открыть» → «Открыть»; либо «Системные настройки» → «Конфиденциальность и безопасность» → «Всё равно открыть».
- **Windows (SmartScreen):** «Подробнее» → «Выполнить в любом случае».

Данные пользователя (настройки, сессия Telegram, база, логи, окружение) лежат вне программы и переживают её обновление и удаление: macOS — `~/Library/Application Support/TG Newspaper`, Windows — `%LOCALAPPDATA%\TG Newspaper`. Остановить консоль — кнопка «Выключить консоль» внизу главной (там же написана версия).

Известное ограничение: шрифты вёрстки «PT Serif»/«Superclarendon» — системные шрифты macOS; на Windows полоса свёрстается запасными (Georgia/Times). Переносы и разбивка всё равно измеряются в браузере, но вид будет отличаться.

**Как выпустить релиз:** `git tag v0.2.0 && git push origin v0.2.0` — GitHub Actions (`.github/workflows/release.yml`) соберёт dmg и setup.exe, прогонит смоук-тест запуска и опубликует релиз с текстом из `packaging/release-notes.md`. Версия берётся из тега.

### Для разработки

**Одна кнопка (macOS).** Один раз выполните `scripts/make_app.sh` — он создаст `~/Applications/TG Newspaper.app` (другой каталог — первым аргументом; после переноса репозитория запустите скрипт заново). Дальше достаточно кликнуть иконку TG Newspaper (её можно перетащить в Dock): консоль поднимется в фоне без окна Терминала и откроется в браузере на `http://localhost:8420/`; повторный клик просто открывает вкладку. Первый запуск ставит зависимости и Chromium — это минута-две. Нужен [uv](https://docs.astral.sh/uv/) (`curl -LsSf https://astral.sh/uv/install.sh | sh`). Лог — `data/console.log`; остановить консоль — кнопка «Выключить консоль» внизу главной страницы. Вся логика запуска — в `scripts/launch.sh`.

**Вручную:**

```bash
uv sync
uv run python scripts/console.py
```

Консоль откроется в браузере (`http://localhost:8420/`, слушает только localhost). Пока проект не настроен, все страницы ведут на **мастер настройки** `/setup` — пройдите четыре шага, править файлы руками не нужно:

1. **Telegram API** — `api_id` и `api_hash` с [my.telegram.org](https://my.telegram.org) → «API development tools». Заходить под **отдельным аккаунтом проекта**, не личным: сессия Telethon — ключ к аккаунту (см. [AGENTS.md](AGENTS.md)). Бот-токен не нужен — сбор идёт по MTProto.
2. **Вход в Telegram** — телефон → код из Telegram → пароль двухфакторной защиты, если он включён. Получается тот же файл сессии, что у `scripts/telethon_login.py` (он остаётся как терминальная альтернатива).
3. **Gemini** — ключ из [Google AI Studio](https://aistudio.google.com/app/apikey), модель (по умолчанию `gemini-3.5-flash-lite`) и **обязательный** `GEMINI_BASE_URL` — адрес прокси через Cloudflare Worker (агент работает из РФ, напрямую Gemini отвечает «User location is not supported»; см. раздел про Cloudflare ниже и `cloudflare-worker.js`). Без прокси шаг не считается пройденным. Кнопка «Сохранить и проверить» делает один дешёвый запрос.
4. **Каналы** — по одному на строку: `username`, `@username` или ссылка `t.me/<username>`. «Сохранить и проверить доступ» проверяет каждый канал через вашу сессию.

Затем консоль ведёт на онбординг по интересам (`/onboarding`) — и можно нажимать «Собрать газету». Настройки можно открыть и изменить позже: ссылка «Настройки» на главной. Секреты при повторном открытии не показываются (только `••••1234`), пустое поле секрета означает «не менять».

Куда пишется: секреты — в `.env` (права 0600), сессия — в `<TG_SESSION_NAME>.session` (0600), каналы — в `config/channels.yaml`; всё это в `.gitignore`.

**Альтернатива — вручную:** скопировать `.env.example` в `.env` и `config/channels.example.yaml` в `config/channels.yaml`, заполнить, затем один раз `uv run python scripts/telethon_login.py`.

**Переменные окружения для проверки без риска для рабочих данных** (в обычной работе не задаются): `TG_NEWSPAPER_DB` — путь к БД, `TG_NEWSPAPER_ENV` — путь к `.env`, `TG_NEWSPAPER_CHANNELS` — путь к `channels.yaml`, `TG_NEWSPAPER_SESSION_DIR` — каталог файла сессии; `TG_NEWSPAPER_HOME` — базовый каталог всех данных пользователя сразу (так работает установленный релиз; по умолчанию — корень репозитория).

```
  personalization.py       — персональная оценка значимости: блок о читателе для промпта, вес и итоговая оценка, обновление summary (Этап 6)

  setup_wizard.py          — логика мастера настройки: запись .env, вход в Telegram, проверки Gemini и каналов
  setup_html.py            — страница мастера настройки консоли
  issue_pdf.py             — PDF номера из PNG-полос (A4 по полосам / склеенные листы A3, Chromium)
  pipeline.py               — единый прогон: сбор → фильтрация → сборка номера
  storage.py                — SQLite-хранилище постов, истории прогонов, состава собранных номеров, профиля читателя и отзывов
scripts/
  console.py               — локальная веб-консоль с кнопкой "Собрать газету"
  render_preview.py        — ручная (пере)сборка номера по сохранённому прогону → data/issues/run_<id>/
  telethon_login.py        — разовый интерактивный логин Telethon (то же делает мастер настройки в консоли)
```

## LLM-классификация: Gemini и обход гео-блокировки через Cloudflare

Этап 2 (фильтрация спорных случаев) использует Gemini (бесплатный тариф) — см.
[implementation-plan.md](docs/implementation-plan.md). Настройка ключа — в
`.env.example` (`GEMINI_API_KEY`, `GEMINI_MODEL`, обязательный `GEMINI_BASE_URL`).

Агент работает из РФ, поэтому прокси **обязателен** (`GEMINI_BASE_URL` — шаг Gemini в мастере
настройки без него не считается пройденным): напрямую Gemini отвечает `400 FAILED_PRECONDITION: User
location is not supported` (IP/VPN считается неподдерживаемым регионом). Обход —
свой прокси на **Cloudflare Worker**, тот же приём, что и в соседнем проекте
[tg_mail_bot](../tg_mail_bot): Google видит адрес Cloudflare, а не IP агента.

1. Зайди на <https://dash.cloudflare.com> → **Workers & Pages** → **Create** → **Worker**.
2. Дай имя (напр. `tg-newspaper-gemini`), нажми **Deploy**, затем **Edit code**.
3. Вставь содержимое [`cloudflare-worker.js`](cloudflare-worker.js) и снова **Deploy**.
4. Скопируй URL воркера (вида `https://tg-newspaper-gemini.ТВОЙ-АККАУНТ.workers.dev`).
5. Пропиши его в `.env`:
   ```
   GEMINI_BASE_URL=https://tg-newspaper-gemini.ТВОЙ-АККАУНТ.workers.dev
   ```

Проверить воркер вручную:
```bash
curl "https://tg-newspaper-gemini.ТВОЙ-АККАУНТ.workers.dev/v1beta/models?key=ТВОЙ_GEMINI_КЛЮЧ"
```
Должен вернуться список моделей (JSON), а не ошибка региона.

> VPN здесь не используется — Worker сам решает проблему гео-блокировки на
> стороне Google. Отдельный VPN понадобится, только если провайдер блокирует
> сам домен `workers.dev` на уровне сети — это уже другая, менее вероятная проблема.

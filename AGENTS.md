## Известные ограничения, зафиксированные до старта разработки

- **Запуск — по кнопке в локальной консоли, не по расписанию.** Нет ни будильника, пробуждающего ПК, ни автозапуска, ни автовыключения по завершении. Пользователь сам открывает консоль (`uv run python scripts/console.py`) и нажимает "Собрать газету" когда захочет; тот же прогон доступен и из терминала (`uv run tg-newspaper`) для headless-запуска без браузера. Период сбора при этом всегда фиксированные последние 24 часа **от момента нажатия кнопки**, не "с последнего успешного прогона" — наверстывание пропущенных запусков сознательно не реализуется, каждый прогон просто берёт свои последние сутки.
- **Запуск консоли одной кнопкой.** `scripts/make_app.sh` собирает `TG Newspaper.app` (по умолчанию в `~/Applications`, в репозиторий не кладётся); приложение вызывает `scripts/launch.sh`: ищет uv, делает `uv sync` и `playwright install chromium`, поднимает консоль в фоне (лог `data/console.log`, pid `data/console.pid`) и открывает браузер; если консоль уже отвечает на порту — только открывает вкладку. Останавливается кнопкой "Выключить консоль" на главной (`POST /shutdown`). Для проверок: `TG_NEWSPAPER_PORT`, `TG_NEWSPAPER_RUN_DIR`, `TG_NEWSPAPER_NO_OPEN`.
- **Релизы (macOS dmg, Windows setup.exe).** Данные пользователя отделены от программы переменной `TG_NEWSPAPER_HOME` (`config.home_dir()`; без неё — корень репозитория, dev-режим не затронут): от неё `.env`, `config/channels.yaml`, `data/` (БД, фото, логи, pid) и сессия Telethon; точечные `TG_NEWSPAPER_ENV/CHANNELS/SESSION_DIR/DB` приоритетнее. В релизе приложение (`scripts/build_release_mac.sh`, `packaging/windows/`) содержит только исходники; при заданном `TG_NEWSPAPER_HOME` `scripts/launch.sh` (и `packaging/windows/launch.ps1`) ставит uv при необходимости, делает `uv sync --frozen --no-editable --reinstall-package tg-newspaper` в `$TG_NEWSPAPER_HOME/venv`, показывает страницу ожидания (`scripts/preparing.html`) и запускает консоль интерпретатором venv. Пути данных — только через функции `config.py` (`env_path/channels_path/db_path/media_dir`), не от `__file__`. Лаунчеры выставляют `PYTHONUTF8=1` (на Windows иначе stdout в файл — cp1251). Сборка и выпуск — `.github/workflows/release.yml` по тегу `v*`; иконки — готовые ассеты `packaging/icons/` (`scripts/make_icons.py`, одноразово). Без подписи; Playwright закреплён на 1.50.0 — не поднимать.
- **Доступ к каналам — MTProto под пользовательским аккаунтом (Telethon), не Bot API.** У ботов нет метода "отдай историю канала за период" — они получают посты только по мере появления (`getUpdates`/webhook), пока подключены. Это несовместимо с механикой агента: сбор должен уметь по требованию отдать историю канала за произвольный период "с этого момента назад", а не только слушать новые сообщения. MTProto умеет отдать историю по запросу — это и есть решающая причина выбора, а не просто предпочтение. Подробности — "Почему MTProto, а не Bot API" в [README.md](README.md) и раздел "Сбор постов" в [docs/project-brief.md](docs/project-brief.md).
- **Сессия Telethon — это ключ к Telegram-аккаунту, а не токен с ограниченными правами.** Хранить как секрет, не коммитить в репозиторий и не логировать. Аккаунт — отдельный, заведённый специально под проект, не основной личный: утечка сессии компрометирует только его.
- **Принтер (HP Color LaserJet Pro MFP M377dw) печатает только по локальной сети.** Облачная печать для этой модели физически недоступна: HP закрыла сервис ePrint в январе 2023 года (переставала выпускать его на новых принтерах ещё в 2020-м), Google Cloud Print закрыт Google ещё раньше, в конце 2020-го. Печатающий код обязан выполняться в той же локальной сети, что и принтер (AirPrint/CUPS/IPP) — вариант с облачным рендером и печатью по email для этого принтера не работает и не будет работать.

## Проект

Пилотный проект: идея — заменить утренний скроллинг ленты печатным газетным номером фиксированного объёма, который агент собирает и печатает сам, без участия человека. Номер — титульная полоса-афиша (один склеенный лист = 2 альбомные полосы, стилизация по обложке Daily Bugle: крикливые анонсы от LLM, кадры, чёрная плашка мастхеда `DAILY · TIMOHA`; статей не печатает вовсе) плюс до 6 альбомных полос мозаики (`pipeline.NEWSPAPER_MAX_PAGES`; один лист A3 = 2 полосы), где и выходят все новости целиком. Рендер — HTML/CSS + Playwright/Chromium (`src/tg_newspaper/layout.py`); что не помещается в номер, LLM-оценка значимости (`classifier.py`) решает сократить нейронкой или выбросить, а не печатать как попало. Работать по этапам из implementation-plan.md, не забегая вперёд открытых вопросов из future-development.md.

## История для дедупа — реально собранные номера

Дедуп против уже опубликованного (`history_dedup.filter_against_history`) сравнивает кандидатов с постами из последних 5 **собранных номеров** (таблица `issue_posts`, напечатанный текст после сокращения), а не с `pipeline_outcomes.included=1` и не с последними 5 прогонами: `included` — лишь "прошёл отбор", часть таких постов не влезает в номер. Состав номера пишет `pipeline.save_newspaper_issue(conn, run_id, result)` — его вызывает `pipeline.assemble_issue(config, conn, run)` — единая сборка номера для кнопки консоли, `uv run tg-newspaper` и `scripts/render_preview.py` (позже печать тоже должна идти через неё). Файлы номера лежат в `data/issues/run_<id>/` (рядом с БД): полосы `page_N.png` и лениво создаваемый кеш `a4.pdf`/`a3.pdf` (`issue_pdf.build_pdf`); `assemble_issue` перед пересборкой удаляет старые полосы и PDF; повторная сборка по тому же `run_id` заменяет состав. В БД, созданной до этого изменения, история пуста до первой сборки номера.

**Порог номера.** Если новостей с `included=1` меньше `pipeline.MIN_ISSUE_NEWS` (8: столько анонсов нужно афише), `assemble_issue` возвращает None до любой работы с файлами и БД; проверку делает `enough_news_for_issue`, текст для пользователя — `few_news_message` (CLI, `render_preview.py`, страница прогона; кнопка «Свёрстать номер» не показывается, уже свёрстанные полосы остаются). **Время:** в БД всегда UTC, всё показываемое пользователю (даты прогонов в консоли, дата номера, имя PDF) — в часовом поясе системы через `layout.to_local`. Выпуск на обложке (Morning/Afternoon/Evening/Night edition) определяется по локальному часу конца окна прогона, `layout.edition_name`. «Выпуск № 0» на обложке — сознательно (pipeline не передаёт `issue_number`), не чинить до конца разработки: см. «Перед завершением разработки» в [docs/implementation-plan.md](docs/implementation-plan.md).

## Рубрики и блок «Новые видео» в вёрстке (Этап 7)

Без рубрик в `channels.yaml` номер верстается ровно как раньше. С рубриками `layout._build_bands` раскладывает новости по секциям (порядок `rubric_order`, каналы без рубрики — последней секцией «Разное»; сопоставление канала без учёта регистра); тиры (одна передовица на номер, `FEATURE_SLOTS` feature, остальное brief) решаются глобально по значимости, группировка в ряды — внутри секции. Заголовок секции — особый `_Band` (`kind="header"`), ставится на лист только вместе с первым рядом секции, на новом листе повторяется с «(продолжение)». Порядок секций строгий: отложенный (не влезший) ряд секции блокирует следующие секции на этом листе (`_fill_sheet`), поэтому внизу листа бывает пустое место — осознанная плата за непрерывность секций. Оно бывает и без рубрик: ряд, не помещающийся в остаток листа, уходит на следующий лист, и внизу остаётся пустая полоса около 1/5 страницы (известное ограничение, см. «Отложенные фичи» в [docs/future-development.md](docs/future-development.md)). Афиша выбирает анонсы по значимости среди поместившихся (`_importance_order`), а не по порядку рядов. Блок «Новые видео» (`kind="videos"`, до `MAX_VIDEOS`, превью из `thumbnail_path` в цвете) — последняя секция очереди; на последнем разрешённом `max_pages` листе место под него резервируется заранее, так что новости его не вытесняют, а уходят в leftover. Поэтому, когда сокращать нечего, `build_newspaper` не выбрасывает сами leftover, а бинарным поиском находит наибольшее число k самых значимых новостей всего номера, которое помещается целиком (пробные рендеры — во временном каталоге и без LLM, финал с анонсами — в каталог номера), остальные выбрасывает (иначе с секциями выбрасывался бы хвост последней рубрики, даже важный; а выброс `len(leftover)` одним махом освобождал куда больше места, чем нужно, и последние полосы оставались пустыми).

**Вместимость мозаики (решения 2026-10-14).** Смайлики и значки вычищаются при вёрстке (`layout.strip_emoji`: текст поста, анонсы афиши, названия видео), в БД остаётся сырой текст. Фото в мозаике — только при `photo_relevance=3` (`MOSAIC_MIN_PHOTO_RELEVANCE`) и в brief-плитках кадром 16:9, в feature 3:2; обложка по-прежнему с 2. Длинные (`BRIEF_SHORTEN_MIN_CHARS`) тексты будущих brief-плиток `build_newspaper` сокращает нейронкой до первой вёрстки, независимо от значимости: высоту ряда задаёт самая длинная плитка; кто станет brief, решает `layout.brief_keys` (правило тиров не дублируется). Хвостовой абзац из одних markdown-ссылок и разделителей режется как подпись при любой длине.

## Мастер настройки в консоли

Первый запуск `scripts/console.py` ведёт на `/setup` (логика — `setup_wizard.py`, страница — `setup_html.py`): Telegram API → вход в аккаунт → Gemini → каналы; "Настройки" на главной открывает тот же мастер. Пока что-то не настроено, остальные страницы редиректят туда (`compute_status()` не падает без `.env`/`channels.yaml`, в отличие от `load_config()`, который пайплайн по-прежнему вызывает как раньше).

**channels.yaml (Этап 7).** Формат: `rubrics: [{name, channels: [...]}]` (порядок = порядок секций), `channels: [...]` (без рубрики; старый формат — только он), `youtube: [{id: UC..., title, source}]`. Единственный разбор — `config.parse_channels_data/read_channels_file` (`ChannelsFile`); `load_config` заполняет `Config.channels` (все телеграм-каналы без дублей), `rubric_by_channel`, `rubric_order`, `youtube_channels`. Карточка каналов — одна textarea, строка `# Имя` = заголовок рубрики (`setup_wizard.parse_channels_text/channels_to_text`, построчно, чтобы заголовки с пробелами не ломались). Карточка "YouTube-каналы" необязательна (не входит в `STEP_ORDER`, на `compute_status` не влияет): при сохранении `youtube.resolve_channel` по сети находит `UC...` (страница канала с `Cookie: SOCS=CAI`, иначе окно согласия; потом RSS для проверки и названия), уже сохранённые `source` не резолвятся повторно; есть ошибка в любой строке — не сохраняем ничего. Обе карточки пишут один файл (`save_channels` атомарный), друг друга не затирают. Видео собирает `youtube.fetch_new_videos` (RSS, без шортсов, превью в `media_dir()/youtube`), сохраняются в `youtube_videos` по `run_id`, чтобы пересборка номера брала те же видео без сети; сбой сбора прогон не роняет.

Где лежат секреты: `.env` (`TG_API_HASH`, `GEMINI_API_KEY`; пишется атомарно, права 0600, чужие строки и комментарии сохраняются) и файл сессии Telethon (0600). Секреты не логируются и не выводятся в HTML целиком — только `••••1234`; пустое поле секрета = "не менять". Бот-токена в проекте нет. Вход в Telegram между HTTP-запросами: клиент переоткрывается на том же файле сессии на каждый шаг, в памяти живёт только `phone_code_hash` (обоснование — в `setup_wizard._run_with_client`). Для проверки во временном каталоге: `TG_NEWSPAPER_ENV`, `TG_NEWSPAPER_CHANNELS`, `TG_NEWSPAPER_SESSION_DIR`, `TG_NEWSPAPER_DB`.

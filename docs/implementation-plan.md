# План реализации: TG Newspaper

Пошаговый план реализации из [project-brief.md](project-brief.md). Этапы построены так, чтобы после каждого был работающий и проверяемый кусок системы, а не абстрактный прогресс. Архитектурно это один скрипт, запускающийся раз в сутки по расписанию (см. "Почему MTProto, а не Bot API" в [../README.md](../README.md)) — этапы ниже это его последовательные части, не отдельные процессы.

## Прогресс

- [ ] Этап 0 — Подготовка
- [ ] Этап 1 — Сбор истории каналов
- [ ] Этап 2 — Фильтрация и дедупликация
- [ ] Этап 3 — Вёрстка и рендер
- [ ] Этап 4 — Печать
- [ ] Этап 5 — Расписание и автономная работа

---

## Этап 0 — Подготовка

1. Завести отдельный Telegram-аккаунт под проект (отдельный номер телефона — переиспользовать номер уже зарегистрированного аккаунта нельзя), получить `api_id`/`api_hash` на my.telegram.org, один раз пройти интерактивный логин Telethon под этим аккаунтом и сохранить файл сессии как секрет.
2. Подписать этот (вспомогательный, не основной личный) аккаунт на все каналы-источники из первого списка.
3. Настроить пробуждение ПК: RTC-будильник в BIOS/UEFI на нужное время; если материнская плата или конфигурация не позволяют — Wake-on-LAN по проводному соединению как резерв.
4. Выбрать и поднять окружение — Python, менеджер зависимостей, репозиторий.
5. Выбрать хранилище состояния между запусками (напрашивается sqlite для первой версии — простое, не требует отдельного сервиса): нужно хранить минимум timestamp последнего успешного прогона.
6. Составить первый список каналов-источников для конфига.

## Этап 1 — Сбор истории каналов

1. Скрипт через Telethon (`iter_messages` с фильтром по дате) забирает историю каждого канала из списка за период с момента последнего успешного запуска (при самом первом запуске — за какой-то разумный период по умолчанию, например сутки).
2. Сохраняет сырые посты (канал, дата, текст, вложения) в хранилище и обновляет timestamp последнего успешного прогона только после того, как весь пайплайн для этого запуска отработал целиком (иначе сбой на более позднем этапе "съест" период и он не попадёт в следующий прогон).
3. Ручной прогон на нескольких реальных каналах — сверка с тем, что реально было в канале за период, включая проверку сценария "пропущен день" (принудительно не запускать сутки, затем прогнать и убедиться, что забралось всё пропущенное).
4. Базовое логирование: что пришло, за какой период, от какого канала.

## Этап 2 — Фильтрация и дедупликация

1. Эвристики отсева "не новостей": медиа без подписи/с короткой подписью, пустые посты и прочие явные признаки (список — по итогам просмотра реальных данных, накопленных на Этапе 1).
2. Интеграция с LLM для классификации спорных случаев (новость/не новость) и для дедупликации новостей, пересказанных разными словами в разных каналах.
3. Эвристика на дословные/близкие копипасты — до обращения к LLM.
4. Прогон на реальных данных за один день, ручная сверка результата с тем, что было в каналах на самом деле — построчно: что отсеялось, что нет, где ошиблась эвристика или модель.

## Этап 3 — Вёрстка и рендер

1. Поднять Playwright (headless Chromium) и собрать HTML/CSS-шаблон газетной полосы: многоколоночная вёрстка через `column-count`, заголовки, декоративные элементы (виньетки, линейки).
2. Настроить размер страницы и DPI под точную печать на A4/Letter — чтобы рендер ложился на лист без пересчёта на Этапе 4.
3. Сгенерировать изображение из реального отфильтрованного набора новостей одного дня, оценить читаемость и вёрстку глазами.

## Этап 4 — Печать

1. Настроить HP Color LaserJet Pro MFP M377dw в локальной сети (AirPrint либо CUPS/IPP-драйвер) — облачная печать для этой модели недоступна (HP закрыла ePrint в январе 2023 года), печатать можно только по LAN.
2. Отправка готового изображения на печать из кода.
3. Обработка очевидных сбоев печати (принтер выключен/недоступен/нет бумаги) — на уровне "не уронить процесс и залогировать", без сложной retry-логики (она — в [future-development.md](future-development.md), если понадобится).

## Этап 5 — Расписание и автономная работа

1. Собрать полный цикл на ПК: пробуждение по RTC-будильнику (или WoL) → автозапуск скрипта средствами ОС сразу после старта → весь пайплайн от Этапов 1–4 → программное выключение машины по завершении.
2. Логирование полного прогона: за какой период забраны посты, сколько отсеяно и почему, что в итоге напечатано.
3. Прогон нескольких суток подряд без вмешательства человека, включая намеренную проверку пропущенного дня (ПК не разбудили/скрипт не запустился) — на следующем прогоне газета должна забрать пропущенный период и напечататься нормально. Это и есть критерий готовности первой версии, а не прохождение отдельных этапов по отдельности.
